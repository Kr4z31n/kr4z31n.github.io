## Solution:

You are provided with two `.E01` files — (these are EnCase Evidence Files). Disk images from a windows System has been provided.

Upon mounting or examining these images, you'll notice that not much user data can be directly accessed. This is because the disks belong to a Windows Storage Pool configured with Storage Spaces, implementing a `Single Parity (similar to RAID 5)` layout across three virtual 5GB disks.

In a typical RAID 5 setup, data and parity information are striped across all disks in the array. The parity allows for fault tolerance, meaning the array can sustain the failure (or absence) of one disk without data loss, as the missing data can be reconstructed using the parity information.

In this challenge, although only two out of the three disks have been provided as .E01 images, data recovery and `reconstruction are still possible due to the single parity mechanism of RAID 5`.

```
Parity is a method of providing data redundancy and fault tolerance. It involves calculating a value (parity) based on the data blocks in a stripe and storing this parity information across all the drives in the RAID array. If a single drive fails, the parity information, combined with the remaining data, allows the system to reconstruct the missing data.
```


Now after uploading both the `E01` files in Disk Drill/UFS/Arsenal Image mounter etc we can reconstruct the Storage pool.

### Question 4:
```
4) What is the Manifest ID of the cargo? Format: All uppercase
```

The only file left is file.log, which contains Zeek logs. Zeek logs are structured text files generated by the Zeek network security monitor. They capture detailed metadata about network activity, such as connections (conn.log), DNS queries (dns.log), HTTP traffic (http.log) and more.

These logs can be analyzed using [Zui](https://www.brimdata.io/download/), a powerful GUI for exploring Zeek logs. It allows for visual inspection, filtering and investigation of network activity from large PCAPs.

Upon loading the logs in Zui and checking the count of packets based on each protocol, we notice that dns has the highest count.

![alt text](upload_9cbb3feac3e7f4011369c724042bc7a7.png)

By examining the DNS logs, we notice that some data was sent from `192.168.56.108` to the domain `aerisxsecmercancia.com`.

We can apply a filter to sort the packets for deeper analysis:

```
_path == "dns" and id.orig_h == 192.168.56.108 | sort ts 
```
![alt text](upload_b3db40abef7269c91ad95c8563e6f268.png)

After filtering the packets based on timestamps, we observe that data has indeed been exfiltrated to the domain `aerisxsecmercancia.com`.

![alt text](upload_dc5ec1463c504379d9408c95a17e544a.png)

Let’s inspect the first packet to understand what kind of data was sent:

![alt text](upload_aa253b9d6cf4924cf917e1b57367354a.png)

It appears that a PDF file was exfiltrated. To analyze this further, the relevant packets can be exported as JSON and reconstructed.

Structure of each query:

| Packet ID | Message type | Session id   |   Seq    |   Ack   | Data    |
|-----------|--------------|--------------|----------|---------|---------|
| 2 bytes   |   1 byte     |   2 bytes    |  2 bytes | 2 bytes | rest of the data     |
|   10bc    |     01       |     20d4     |   ae0a   |  9046   | 255044462d312e340a25d3ebe9e10a312030206f626a0a3c3c2f5469746c65202846696e616c5f706c616e290a2f50726f64756365722028536b69612f504446206d31333620476f6f676c6520446f63732052656e6465726572


To reconstruct the PDF, we extract all data fields from DNS queries with the same ACK value (9046), remove the protocol-specific header (first 9 bytes of each encoded payload), concatenate the remaining hex data and convert it to bytes.

```python
import json
in_file = "query.json"
out_file = "reconstructed.pdf"

with open(in_file, "r") as f:
    data = json.load(f)
hex_str = ""

for obj in data:
    line = obj["query"]
    packet_id = line[:4]
    message_type = line[4:6]
    session_id = line[6:10]
    seq = line[10:14]
    ack = line[14:18]
    data_field = line[18:]
    domain = line[-23:]

    if ack == "9046":
        line = data_field[:-23]
        line = line.strip()
        parts = line.split(".")
        line = ".".join(parts[:4])
        line = line.replace(".", "")
        hex_str += line

pdf_data = bytes.fromhex(hex_str)
with open(out_file, "wb") as pdf:
    pdf.write(pdf_data)
```

After reconstructing the pdf, Manifest ID can be found in it.
